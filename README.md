# wisp-drug

基于 [wisp-science](https://github.com/xuzhougeng/wisp-science) 的下一代药物研发平台。本地优先，证据可回溯。

wisp-science 提供项目、会话、子代理、技能执行和远程 Run。wisp-drug 在这套工作台上回答药物研发的问题：靶点值不值得做、变异说明什么、分子怎么设计、成药性是否成立、证据能否综合成一个可追溯的结论。

本仓库是产品分支：[Yu-Qiao-sjtu/Qiao_lab](https://github.com/Yu-Qiao-sjtu/Qiao_lab)。

## 我们做什么

起点是 wisp-science 这条开源科研路线，不是任何闭源药物工作台。其他产品的拆解只作为工程情报。

从这类拆解里留下的，是与厂商无关的技能组织方式：

- 复杂问题拆成可组合的技能，组合写在技能说明里
- 入口保持简短，深文档放在 `references/`，用到再读
- 示例输入同时当作测试夹具

不带进产品的，是私有镜像分发、强制云端执行、只能走计费中继的模型，以及换一层身份的营销壳。能力沿具体研发问题生长，不按竞品功能清单复刻。

## 界面

打开应用后是一条项目里的研究对话，旁边可以预览项目文件。

| 界面 | 药物研发里做什么 |
|---|---|
| 项目 | 一条研发线，例如一个靶点加一个适应症。文件、对话和 Run 都留在这个目录 |
| 对话 | 用自然语言提出问题。`/` 加载技能，`@` 附上结构文件、表格或已有报告。批准卡默认开着 |
| 文件预览 | 打开评估报告、适应症档案和 JSON 证据 |
| Runs | 对接、预测、动力学走这里。命令、日志和退出状态留在 Run 记录里 |
| 设置 | 自备模型；确认技能；登记本机、WSL 或 SSH 主机 |

密钥留在操作系统钥匙串，不写入项目数据库。

## 第一条工作流：靶点评估

在项目对话里加载 `target-evaluation`。它回答：这个靶点在这个适应症里应该 **advance**、**hold** 还是 **stop**。

1. 先确认靶点和适应症身份。身份没对齐之前，不展开检索。
2. 疾病背景加载基座技能 `indication-dossier`：患者人群、标准治疗和关键试验。
3. 四条证据线写入项目文件：人类遗传与临床、适应症内机制、所述模态是否可做、安全性与临床竞争。
4. 数字、分期和竞品名称必须带原始链接。没有来源就保持为证据不足。
5. 结构预测、对接和分子动力学另开 Run，程序和权重留在执行主机上。

技能说明在 `skills/target-evaluation/SKILL.md`。后续技能按同一方式长出：变异解读、分子设计、成药性、证据综合。契约见 [docs/skill-format.md](docs/skill-format.md)。

## 现在有的

现在可以用基座窗口和捆绑技能 `target-evaluation`。领域词 `drug-discovery` 已写入技能目录。

还没有单独界面的部分：靶点决策卡片、四条证据线对照视图、分子结构画布，以及 wisp-drug 自己的安装包。决策先进入项目文件和预览，计算进入 Runs。
